# 写入协议（outline-maintainer 详细模块）

> **何时读：任何对库文件的落盘动作前——收录 / 维护 / 体检 / 导入的一切写入。** 检索刷 `活` 只豁免第 4/5/6 条，**不豁免第 10 条写锁**（写锁规则也在本模块）。
> 内容 = §7 写入协议全文 + §17 操作日志行格式（自 SKILL.md v31 下沉，§ 编号沿用不变）。
> 检索行与落空记录的格式常驻 SKILL.md §17（检索会话也要写它们），不在此重复。

# 7. 写入协议

**适用范围**：收录 / 维护 / 体检 / 导入（§20）的写入。§5 检索命中刷新 `活` 豁免本章的版本号、自检与日志（第 4、5、6 条），但**不豁免第 10 条写锁**——任何对 `大纲.md` 的写入都要先持锁。

1. **不做自动备份**：版本由用户 git 管理，你不 commit、不建备份目录。正因为没有自动备份，「最小编辑」是硬约束。
2. **只做最小编辑**：新增插在锚点行之后；修改只替换该行指定字段；删除只删目标行。**禁止整文件重写 `大纲.md`**。
3. **知识条目是两处写入**：先写正文文件（新建），再写 `大纲.md` 的条目行。顺序不能反——反了会有一瞬间条目指向不存在的文件。正文文件只能新建或追加指定段落，**禁止重写已有正文全文**。
4. 更新文件头：`<!-- vN+1 ｜ 条目 M ｜ 更新 日期 -->`。
5. **写后自检并报告**：本次 `+a / ~b / -c` 行；条目数 M（只数 `- **` 开头的行）；目录合计是否等于 M；知识条目的正文文件是否都已落盘。用 `check_outline.py` 复核，硬错误必须清零再报，警告照实回报。
6. **追加一行操作日志**（格式见本模块末尾「操作日志行格式」）。不写日志的写入视为未完成。
7. 只有用户说「导出完整文件」才输出全文，且分段（第 i/n 段），末段报总行数与条目数——防止截断丢数据。**正文文件不走这条**，需要时单独导出单个文件。
8. **改字段 / 改结构前，先 `grep` 旧字段名。** 每次字段变更都要扫全篇，把出现旧字段名的地方一起改：定义段、示例、落盘清单模板、骨架、体检表、脚本注释与 docstring。**只改定义段 = 必然留坑**——这个 skill 已经因为漏扫产生过 7 处自相矛盾（旧 `范围`、旧 `记`/`用`、与留证规则打架的"必须留档"）。
9. **落盘成功后清理解析缓存**：本次收录若用了 material-parser，写后自检（第 5 条）通过即删除该材料的缓存目录——`material-parser/scripts/common.py --clean <缓存目录>`（只删 status=done 的，未完成任务会拒删保断点）。**唯一例外：在线视频走转写路线的产物保留**（库内无原件，缓存转写是唯一本地文本记录），并在报告说一句「转写已留档于缓存，可随时手删」。缓存是收录期间的工作台，不是档案——长期留档的只有正文里的逐字引用+页码/时间戳（§16）。
10. **落盘互斥（多会话场景，本章一切写入通用）**：实际动笔前先 `write_lock.py <大纲.md> acquire` 取 `<库根>/.写入锁`。取锁失败 = 另一会话可能正在写入：等几秒重试一次，仍失败就停下报告用户「另一会话在写，稍后再试」，**不排队硬等、不 `--force` 抢锁**。锁内顺序：重读 `大纲.md` → 重验落盘清单（锚点行还在不在、条目名是否已被抢先写入——被抢先的条目降级为「跳过」或改「更新」，重新报数）→ 执行最小编辑（知识条目先写正文文件再写索引行，**正文的新建/追加也在锁内**——防两个会话并发写同名正文）→ 写后自检（第 5 条）→ 追加日志（第 6 条；检索行同理）→ `release --token 令牌`。**人工确认阶段不持锁**（不能锁着库等用户）。租期默认 300 秒，忘 release 会自动过期，不会死锁；大批量导入（§20）预估超时的加 `--lease 1800`。

**目录结构**

```
大纲/
├── 大纲.md     # 索引：目录 + 条目行。只有这一件事，别的都不放
├── 日志.md     # 操作日志 + 落空记录（只追加，低频读）
├── .写入锁    # 落盘互斥锁（§7 第 10 条，租期制短暂存在），不进 git
├── 知识/       # 知识条目正文，一条一文件，按子类分目录
│   └── 信息管理/
│       └── 某某方法.md
├── 索引/       # 派生层：大纲.db（可由 build_index.py 随时重建），不进 git
└── 素材/       # 可选。默认不存在，只有孤本材料才建，不进 git
```


**`大纲.md` 骨架（新建库样板）→ `详细/条目格式与正文.md` 末尾。**

目录由正文派生，只写「分类 + 条数」，不写条目名；每次写入后重算。

**不要让 `大纲.md` 长出第四块。** 日志、待办、备注区、统计数字都不许往这里加——那正是它变成垃圾堆的方式。想加东西，先问是不是该进 `日志.md` 或某个正文文件。

## 操作日志行格式（§17 的写入侧）

**只追加，不改历史行。** 格式（字段固定，用 ` ｜ ` 分隔，供脚本统计）：

```
- 2026-10-23 v6 ｜ +7 ~0 -0 ｜ 收录 B站@某UP「标题」03:12 ｜ 跳过 0 ｜ 待核验 7 ｜ 备注 无
```

| 字段 | 内容 |
|---|---|
| 日期 版本 | 落盘当天日期 + 写入后的版本号 |
| 增减 | `+a ~b -c`（新增/修改/删除条目数，正文文件记为 `+正文 n`） |
| 动作 | 收录/更新/失效/体检/抽查/导入 + 来源简称 |
| 跳过 | 本次因去重跳过的条数 |
| 待核验 | 本次落盘后仍带 `待核验/待补充` 的条数（累计值） |
| 备注 | 一句话。**只写事实和理由，不写评价** |

- 每次写入都追加 1 行，包括只改一个字段的小改动。
- 这是"为什么"的唯一记录——为什么跳过、为什么标待核验、为什么这个分类没有合并。`git log` 记的是文件状态，不记判断依据。
- **不主动裁剪**。用户说「归档日志」时，把超过 1 年的行移到 `日志归档.md`，原文件只留近 1 年。
- **只记使用，不记开发**：技能与脚本的迭代史写 `<技能目录>/outline-maintainer/变更记录.md`，不占这里（2026-10-25 分流）。
