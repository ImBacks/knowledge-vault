# 9. 素材处理与大文件

## 通用铁律

**提取出来的东西不等于原文。** 凡是由概括、推断、跨页拼接得出的内容，必须在正文里标 `（推断）`；凡是从扫描件 / 画面 / 字幕里认出来的文字，标 `（据识别，可能有误）`。**不确定就标，不要抹平。**

- **大文件先解析**：超过阈值（见下表）的文档与音视频，先跑技能内置 `material-parser` 子模块（`<技能目录>/material-parser/`，手册见其 解析手册.md），读概览与分块产物，不逐页/逐帧读原件。**缓存根**：脚本向上找 `大纲.md` 自动定位库根（`<库根>/解析缓存`）；技能装在库根之外且向上找不到时，设 `MATERIAL_PARSER_CACHE=<库根>/解析缓存` 或传 `--cache-root`（三级落空会报错，不静默乱建）。产物收录落盘成功后即删（§7 第 9 条）；引用仍指向原文件 + 页码/时间戳。

  **大文件的定义（成本比 + 阈值表）**：
  - 真正的定义是**成本比**：预估两条路线——工具路线（脚本解析 + agent 读产物） vs agent 直读。**工具路线 ≤ 直读的一半（快 2 倍以上）→ 大文件**。2 倍是硬门槛：多一道工序、多一个缓存目录，优势不悬殊就不值。直读的单价按**调用方模型的真实读法**计——能原生整份读入（自带 PDF / 长文档输入、直接看视频）的模型直读远快于逐页慢读，不套通用估值（§4 第 0 步的过阈值豁免同此）。
  - 阈值表是成本比的**预计算答案**，90% 情况直接查表：

    | 类型 | 阈值 | 依据的量 |
    |---|---|---|
    | PDF / EPUB | > 30 页 | 页数 = agent 直读要逐页过的量（fitz 兼容格式 xps / mobi / cbz 同理可试） |
    | 视频 | > 10 分钟 | 时长。**分辨率不是成本**：转写只读音轨、抽帧按时间采样且帧会被降采样；按文件大小判会误判（10 分钟 4K 片头 2GB vs 2 小时 480p 课程 700MB） |
    | 音频 | > 10 分钟 | 时长 = 转写耗时 |

  - **元数据拿不到 → 按文件大小粗估兜底**：视频 > 500MB、PDF > 20MB（大概率扫描件 / 大部头）→ 按大文件处理。
  - **表外情况现场估两个数**：直读 ≈ 页数 × 数秒/页（原生整份读入的模型另算），或时长 × 采样帧数；工具路线 ≈ 转写时长 × 0.3~0.6（CPU int8）/ PDF 文本层秒级 / OCR 1~2 秒每页，再加读产物几分钟。工具 × 2 ≤ 直读就走工具。
  - **不经闸门的类型**：docx / pptx / xlsx（官方 skill 即文本提取，无逐页慢读）、网页 / 纯文本（token 量可控，分段读）、单张图片（永不算大）。**图片批量 > 20 张**：提示分批处理，不走解析。

## 网盘

只能读到文件列表（名称/大小/类型）时，作用必须写成「据文件列表：…」，不得声称打开过包内内容。需要登录、需要提取码、内容在压缩包里 → 先问提取码；拿不到就标 `（待补充）（待核验）`。一个链接装了多个独立东西，按 §4 拆条，来源指向同一链接不算重复。
