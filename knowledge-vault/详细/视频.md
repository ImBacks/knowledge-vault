# 视频收录细则（knowledge-vault 详细模块）

> **何时读：收录视频 / B站 / 抖音 / 直播录像动笔前。**
> 解析工具的用法与开关见 `../material-parser/解析手册.md`（不在此重复）；主流程在 `收录.md` §4，落盘走 `写入协议.md` §7。

## 视频

- **有音频或字幕**：转文字再抽取。长视频只抽「明确推荐 / 演示过」的对象，跳过广告与寒暄。一个长视频讲一个方法论 → 1 条知识条目 + 1 个正文文件，时间点做成二级标题。
- **无音频，或用户说「看看这是什么」**：看画面——界面里的软件名、URL、按钮文字、操作流程。
- **解析开关按视频类型裁（杠杆见 material-parser 手册「命令」节；工具不替人分类，判断交给 agent）**：纯口播 → 默认转写即可，不开 `--keyframes`（画面不解码，零浪费）；无口播/纯画面+背景乐 → `--no-transcribe --keyframes`（跳过转写只抽帧）；讲述+展示混合（讲义/教程/录屏直播/举物讲解）→ `--keyframes`——场景检测抓翻页/切屏，**讲述锚点**抓「看这个/如图/手上」这类话指向画面而画面没变的瞬间；超长幻灯片 → `--max-frames 300` 放宽封顶；指物用词特殊 → `--cue-words 锅,焊点` 换词表。转写 0 段时脚本会提示纯画面路线。
- **主动核验（必做，发挥能动性）**：视频没念出链接时，两条路都要走——
  1. 按条目名字联网搜索仓库 / 官网（名字可能被口播念错，多试几个变体，如口播 Impossible 实为 impeccable）；
  2. 逐帧看画面：URL、仓库界面、弹幕/字幕里出现的链接都提取出来。
  - 搜到的地址必须与视频内容对得上（名字一致、作用吻合）才采用；采用自行搜到的仓库时，备注注明「仓库为自行核验」。
  - 对不上或搜不到 → 来源写视频出处，作用末尾标 `（待补充）`，不硬凑。

## 抓取路线图（在线 URL，按序走，不跳级不试错）

| 级 | 动作 | 前提 | 失败时 |
|---|---|---|---|
| 1 | CC 字幕（秒级） | 无 | 站点没提供 → 走 2 |
| 2 | AI 字幕 | `--cookies <浏览器名或 cookies.txt 路径>` | 报登录态问题 → 按下方 cookies 指引配好后重试一次 |
| 3 | 下载音频本地转写 | 同上（下载也要登录态的站点必配） | yt-dlp 报错原文透传给用户；仍失败 → 走 4 |
| 4 | browser-use 兜底：真浏览器开分享页 → 从播放器/页面源码取视频地址 → 下载 → 按 URL 原文处理 | 无 | 反爬每次不同，照现场判断，不硬套 |
| 逃生门 | **抓不到就不抓**：请用户自己下载，丢本地文件按本地路线解析（零反爬） | 无 | 来源写 URL，标 `（待核验）`，不编造 |

- **cookies（登录凭据）**：用 cookies.txt（推荐）或浏览器名。获取与落位见下方「获取 cookies」节。
- **为什么必须扩展导出（2026-10 实测，勿再试直读）**：① Chrome 运行中锁库（yt-dlp `PermissionError`，issue #7271）；② 关库后 Chrome 127+ 「应用绑定加密」，外部程序含 yt-dlp 官方解不开；③ Chrome 136+ 禁止对默认用户目录开调试端口（CDP 接管失效）；④ ZCode 自动化浏览器是隔离沙盒，没有用户的登录态与扩展。四墙齐备——**让浏览器自己导出是唯一畅通路**，别在会话里重走实验。
- **抖音直连现状（2026-10 实测）**：脚本已内置短链预解析与 `/note/→/video/` 重写，抽取器能接住视频；但签名算法对 web detail JSON 仍 403——新鲜登录 cookies、真实 Chrome UA 都无效，这是 yt-dlp 与抖音的签名军备竞赛。**直接走第 4 级**（实测端到端 <20 秒：浏览器开页 9.4s → 页面 `<video>` 取直链 → 下载 1.8s → 本地解析 3.6s；同一视频在路线图定型前试错 3-4 分钟）。零口播短视频收 `--no-transcribe --keyframes`。
- **转写设备已默认 auto**：自动检测 N 卡走 GPU（int8_float16），缺 CUDA 运行库自动回落 CPU 并说明——不用传参；`--device cpu` 强制 CPU，`--model medium` 属重负载档由用户点名。
- **用户问「当前配置 / 用的什么工具 / GPU 开没开」** → 跑 `python scripts/common.py --config`，把输出翻成一句话（引擎、设备、模型、cookies、缓存根），不凭记忆背配置。

## 获取 cookies（用户说「获取cookies」时走这套，一站一次）

1. **前置（只做一次，用户自己做）**：用户浏览器装「Get cookies.txt LOCALLY」扩展并登录目标站点（抖音/B站/YouTube…）。**默认不代装、不主动打开扩展商店**——环境侦察（`cookies导出.md` 第 1 章第 3 项）发现未装才提醒用户自行安装，用户问怎么装再给商店链接。
2. **导出（agent 全自动，用户不动手）**：按 `详细/cookies导出.md` 执行——先跑第 1 章环境侦察，再按决策树走路线 A（键盘流）→ B（Win32 鼠标）→ C（a11y）→ D（全站导出兜底），在用户的真实浏览器里完成导出；交付用 Move、校验只看行数与字段名（方案内含安全红线）。
3. **落位**：agent 把下载目录里最新的 `cookies.txt` 移到 `<技能目录>/cookies/<站点>.txt`（`douyin.txt` / `bilibili.txt` / `youtube.txt`，按站点命名；目标文件已存在 = 覆盖前问一句「旧的过期了吗」）。
4. **登记**：SKILL.md 配置节「视频抓取 cookies」行保持默认目录即可（用户自定义过的尊重自定义），报一句「douyin cookies 已就位」。
5. **验证**：拿一个该站点真实 URL 带 `--cookies <文件>` 试抓一次——成功报「已闭环」，失败把 yt-dlp 报错原文贴给用户（多半是登录态过期或站点改版，重走 2）。
- **安全**：cookies = 登录凭据，等同密码——不外传、不进 git（仓库 .gitignore 已排除 `knowledge-vault/cookies/`）、不写进日志/条目/报告，agent 只在命令行里引用路径（§11 动账号凭据先确认的底线不变，本流程即用户显式授权的范围）。
- **使用**：抓取时按 URL 域名自动挑 `cookies/<站点>.txt` 传给 `--cookies`；没有对应文件 → 提示「该站还没获取 cookies，说『获取cookies』」并按路线图继续（不裸抓、不卡死）。
- **全量导出文件的处理**：用户给「Export All」全量 cookie 文件（含全部网站凭据）时，agent 只 `grep` 提取目标站点的行落到 `cookies/<站点>.txt`，**整份文件绝不复制、不移动进技能目录或仓库、不写进日志与报告**；提取完成即提醒用户删除原文件。
- **过期**：抓取报登录态失效（如「请登录」「要新 cookie」）→ agent 按方案**自行重新导出**（同第 2 步），不回退到让用户手动点。
