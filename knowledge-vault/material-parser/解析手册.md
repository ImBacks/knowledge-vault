# 素材解析手册（material-parser · 内置可选模块）

版本：v1.12（2026-10-26）。本文件是 knowledge-vault 技能内置子模块 `material-parser/` 的**使用手册（不是技能，不注册、不触发）**；模块位置 `<技能目录>/material-parser/`，命令均在本目录下执行。Python 路径约定同 knowledge-vault 配置节。**模块定位：素材加工两层——① 解析（确定性字节处理：PDF/音视频 → 文本与帧，本手册主体）；② 蒸馏（判断型加工：长内容转写 → 方法论/可执行技能，见「蒸馏」节，agent 执行七阶段、脚本做脚手架）。**

## 何时用（与 knowledge-vault §9 衔接）

- **大文件**：>30 页的 PDF / EPUB、>10 分钟的音视频 → 先跑本工具解析，读产物而非原件。阈值的本质是**成本比**：工具路线（解析+读产物）比 agent 直读快 2 倍以上才算大文件，判据与阈值表见 knowledge-vault §9。
- **小文件直接读原件更快**，不必走解析（解析+读产物两步反而慢）。
- **蒸馏触发**：材料是方法论密集型长内容（课程 / 长会话 / 长访谈 / 书籍），且用户要「提炼方法论」或「做成技能」→ 解析拿转写后走「蒸馏」节；工具/短材料不蒸馏。判据与产物落点见该节。
- 产物在 `<库根>/解析缓存/<文件名>-<sha1前10位>/`，**随时可整目录删除重建**，删了不丢任何源数据。**定位是收录期间的工作台，不是档案：入库落盘成功后即删**（knowledge-vault §7 第 9 条驱动；手动删用 `common.py --clean <目录>`，未完成任务会拒删保断点）。**蒸馏产物是唯一反向例外：它是交付物本身，先拷出落库再清缓存**（见「蒸馏」节生命周期）。

## 能力总览与可选加速 → 项目根 README.md

三层菜单（默认开箱即用 / 按用途可选 / GPU 加速档）的人类可读主本在**项目根 `README.md`「工具清单：默认与可选」**，以彼处为准——本手册不复制，防双写漂移。运行时的现场版是 `common.py --doctor`（探测本机实际状态并给精确命令）；独立安装、README 不在旁边时，`requirements.txt` 的分组注释是随技能走的完整清单。新用户问「技能怎么用」/「帮我初始化」时，把该三层一次性端出：只陈述事实与代价，不代做安装决定。

## 铁律

1. **引用一律指向原文件 + 页码/时间戳**，禁止把 `解析缓存/` 路径写进任何知识条目或正文——缓存可删，引用不能悬空。chunk 内自带 `【p12】`/`[00:12:34]` 标记，直接引用标记对应的原件位置。
2. **OCR / 转写文本属「据识别」**：引用前按页码/时间戳回查，入库时标 `（据识别，可能有误）`（knowledge-vault §9 通用铁律）。
3. **转写默认 small 模型**，中文专有名词/术语错误率不低；要更准用 `--model medium`（约 2 倍时长）。事实性引用（数字、人名、链接）必须回查后才能落库。
4. **长任务后台跑**：几小时视频的转写在 CPU 上要几十分钟，用后台任务执行，不要阻塞会话。

## 命令

```
D:\python\python.exe scripts/parse_pdf.py <pdf/epub> [--chunk-pages 50] [--dpi 150] [--no-ocr] [--force]
D:\python\python.exe scripts/parse_video.py <视频/音频路径或URL> [--model small] [--language zh]
    [--chunk-sec 600] [--keyframes] [--no-transcribe] [--max-frames 120] [--cue-words 词1,词2]
    [--keep-audio] [--device cpu|cuda] [--cookies chrome|edge|firefox|brave] [--force]
D:\python\python.exe scripts/common.py --clean <缓存目录> [--force]   # 入库后清理：done 才删，未完成拒删保断点
D:\python\python.exe distill/scripts/cangjie.py doctor               # 蒸馏子模块自检（D·蒸馏组：PyYAML 必选）
```

- **parse_pdf（PDF / EPUB，fitz 兼容格式 xps/mobi/cbz 同样可试）**：文本层秒级直提；文本薄的页（<25 字符/页）逐页 RapidOCR 兜底（CPU 约 1~2 秒/页，逐页断点）。有书签按章节分块，无书签每 50 页一块。概览.md 自带章节表（满足「>30 页先出章节表」）。
- **parse_video** 在线视频三级链路：①CC 字幕（免登录秒级）→ ②AI 字幕（`--cookies chrome`，浏览器需已登录）→ ③下载音频本地转写兜底。本地视频/音频直接转写。`--keyframes` 抽关键帧+缩略图对照表，**双信号**：场景检测抓画面突变（翻页/切屏/镜头切换）；**讲述锚点**抓「话指向画面」的瞬间——转写/字幕命中"看这个界面/如图/手上"类用语即在该时间戳抽帧，举物讲解、指屏幕角落这类**画面没变**的时刻只有锚点能抓到。锚点优先保预算、场景帧均匀填充、±3 秒去重，封顶 `--max-frames`（默认 120）；在线拉流封顶 1080p（缩略图足够）。
- **在线视频站点**：yt-dlp 支持的均可（B站/抖音/TikTok/YouTube 等），三级链路同样适用。抖音类预期：基本无 CC/AI 字幕、确定落兜底转写（十几分钟视频 CPU 转写 5~10 分钟），部分内容需 `--cookies`；取不到视频信息时自动退回按 URL 成键，不会卡死。
- **--device cpu|cuda（转写设备，默认 cpu）**：默认 CPU 全功能；cuda 需 N 卡 + CUDA 运行库（可选安装，菜单见项目根 README「工具清单：默认与可选」）。显式 cuda 而不可用 → 报错退出不静默回落；`--device` 不进缓存键，换设备沿用已转写缓存。
- **按材料类型选开关（AI 裁量，不是硬规则——工具提供杠杆，类型判断交给调用方）**：纯口播（信息在讲述里，画面只是人在说话）→ 默认即可，不加 `--keyframes`（画面根本不解码）；无口播/纯画面+背景乐（幻灯片、录屏展示）→ `--no-transcribe --keyframes`（跳过字幕与转写）；讲述+展示混合（讲义、教程、举物讲解、录屏直播）→ `--keyframes`；超长幻灯片录像 → `--max-frames 300` 放宽封顶；指物用词特殊（做菜/手工/电路）→ `--cue-words 锅,面团,焊点` 换词表（空串禁用锚定）。转写结果 0 段时脚本会提示纯画面路线；纯画面缓存重跑去掉 `--no-transcribe` 自动补转写。

## 产物结构

```
解析缓存/<名>-<sha1前10>/
├── 概览.md        # 先读这个：章节表/时间范围、chunk 索引、关键帧表
├── chunks/        # 分块正文，按需读对应块，别全读
├── manifest.json  # 参数、进度、chunk 清单（机器用）
├── transcript.srt / segments.jsonl   # 视频类
├── keyframes/     # --keyframes 时：kf_NNNN.jpg + contact.jpg 拼图
└── lock.pid       # 任务运行期间存在
```

**AI 读法**：先读概览定位 → 再读 1–3 个相关 chunk → 引用时用 chunk 里的页码/时间戳标记指向原件。三级下钻，不要全量读 chunks。

## 蒸馏（distill/ = cangjie-skill v2.5.0 功能子集）

**定位**：解析产出「文本」，蒸馏把文本加工成「可复用的方法论与可执行技能」。七阶段流水线（全文理解 → 并行抽取 → 三重验证 → 能力卡片 → Zettelkasten 链接 → 压力测试 → 编译交付）由 **agent 按规范执行**——`蒸馏规范.md` 是执行规范（上游 SKILL.md 去 frontmatter），`methodology/` 是分阶段细则，`extractors/` 是五类提取器的提示词；`scripts/cangjie.py` 负责机械部分（doctor 自检 / compile 编译打包 / validate 校验）。**工具提供杠杆，判断交给 agent**（v25 原则）——cangjie 不是一键黑盒，是给 agent 用的脚手架。

- **触发**：用户明说「做成技能 / 蒸馏一下」，或方法论密集材料（课程 / 长会话 / 长访谈 / 书籍）收录且内容确有方法论时。工具条目、新闻、单篇短文不蒸馏。
- **前置**：解析先行——音视频先出转写（parse_video），PDF 先出文本（parse_pdf），蒸馏吃的是转写/文本产物。依赖只多一个 PyYAML（requirements「D·蒸馏」组；`--doctor` 报状态）；缺 PyYAML → 提议一次（同会话规则同 §4 闸门），拒绝则**降级 agent 手工蒸馏**（按 蒸馏规范.md 的阶段人工执行，跳过 cangjie.py 编译校验），报告注明。
- **工作目录**：中间产物一律放 `<缓存根>/<材料>-<sha1>/蒸馏/`（含 `.cangjie/` 能力卡），与解析缓存同生命周期管理。
- **产物落点（三层，对应 knowledge-vault 的蒸馏分层）**：① 读懂了什么 → 知识条目正文（`知识/` wiki 文件，Obsidian 可读）；② 方法论 / 清单 / 决策框架 → 正文「方法论」节或独立聚合页；③ 可执行技能 → `蒸馏规范.md` 流程编译出的 skill 包拷进**技能目录**（不是库内），库里收一条形态 `Skill` 的工具条目指回去，`- 相关：[[...]]` 互链知识条目。
- **引用纪律**：能力卡与正文的引用沿铁律 1——指向原件页码/时间戳；能力卡之间引用条目名。
- **生命周期**：蒸馏产物是交付物，**先拷出落库（正文 / 技能目录），再按 §7 第 9 条清缓存**——`.cangjie/` 中间卡不留档，留档的是正文引用与技能包本体。
- **边界（上游原文）**：做方法论 / 决策框架 / 清单 / 原则 / 概念体系；不做书摘、读后感、作者人设角色扮演。

## 缓存语义

- **缓存根定位（三级）**：`--cache-root` 参数 > `MATERIAL_PARSER_CACHE` 环境变量 > 脚本向上找 `大纲.md` 自动定位库根（`<库根>/解析缓存`，模块嵌在技能目录任意深度都能找到）。三级都落空 → **运行时报错**要求显式指定，绝不静默把缓存建到陌生位置。技能装在库根之外（如技能目录且库根不在上层）时，向上找不到库根，必须设环境变量或传参。`--doctor` 会报缓存根及其来源。
- **按 sha1 查找缓存**：文件改名不失效（manifest 记 aliases）；URL 优先按「站点+视频ID」成键（短链/参数变体同一视频共用缓存，B站分 P 单独成键），取不到视频信息时退回规范化 URL 串。重跑同一本地文件时走缓存根级 `sha1-index.json`（记 源路径→size/mtime/sha1）：未变即免整文件重哈希——几 GB 视频的"秒回"不再被 10 秒/GB 的 sha1 拖住；索引只是提示，不匹配就重算。
- **命中条件**：status=done 且参数一致（PDF：chunk-pages/dpi/OCR 开关；视频转写路线：model/language，**--device 不参与判定**——换设备沿用已有转写缓存，要按新设备重转用 `--force`）。参数不匹配 = 不命中，重跑流程——但**慢步骤按参数复用**：OCR 逐页复用（改分块不重识别），转写在 model/language 未变时复用（改 chunk-sec 只重新分块），keyframes 是叠加产物、缺了单独补不重转写（`--max-frames` 变化会重抽帧；`--cue-words` 换词需 `--force`）。纯画面（visual）路线的缓存，重跑去掉 `--no-transcribe` 自动补转写。manifest 的 `transcribe_done` 标记转写已完成：即使产物被手动删，重跑也只按现有段落重建，不重下音频。
- **运行锁 lock.pid**：同目录已有活进程 → 拒绝运行并提示，指路是「另一会话正在解析同一材料：不要换参数或 `--force` 强跑，等它结束后重跑同一条命令即命中缓存秒回」；进程已死 → 自动清理陈旧锁续跑（`--clean` 同样判活，陈旧锁不再永远挡住清理）。长任务后台跑时避免并发重跑同一文件。多会话解析**不同**材料互不影响（各材料独立缓存目录）；同一材料的重复解析由「缓存键 + 运行锁」收敛为一次解析、其余等待复用。
- **断点续跑**：中断（kill/断电）后重跑同一命令自动续——PDF 按 OCR 页、视频按转写段落落盘，已完成的单位不重做。
- **中间文件生命周期**：转写成功后中间 wav/下载的媒体默认删除（几小时视频是 GB 级）；中断时保留供续跑；`--keep-audio` 强制保留。
- **缓存生命周期：工作台，不是档案**。收录落盘成功后即删（knowledge-vault §7 驱动，或手动 `--clean`）；**唯一例外：在线视频走转写路线的产物保留**——库内无原件，缓存转写是唯一本地文本记录（重拉要几十分钟）。未完成任务的缓存是断点，`--clean` 拒绝删除（`--force` 才删）。

## 环境

- **平台前提**：以 Windows 为第一环境（selftest 的 TTS 用 PowerShell、ffmpeg 指引走 winget）。macOS / Linux 上 pip 依赖与解析脚本主体可用（锁、缓存、断点均跨平台），ffmpeg 用系统包管理器装，selftest 的 TTS 转写项会因取不到中文 voice 报缺项——属预期，其余项照常验证。
- 安装依赖（**可选，按用途**，不必全装）：`D:\python\python.exe -m pip install -r requirements.txt` 装全；只想解析 PDF 就只装 requirements.txt 里 A 组。
- ffmpeg 缺失时：`winget install Gyan.FFmpeg`（先征得用户同意），装完重开终端。
- whisper 模型下载默认走 hf-mirror（脚本内置 HF_ENDPOINT，可用环境变量覆盖）。
- 自检：`D:\python\python.exe scripts/common.py --doctor`——依赖/ffmpeg/GPU/蒸馏探测，并**按用途报告**（「要转写还缺什么 + 精确 pip 命令」）。GPU 探测三态：未装 ctranslate2 → 跳过；无 N 卡 → ℹ 默认 CPU（功能完整）；有 N 卡 → 已装 CUDA 运行库打 ✅（就绪，加 `--device cuda` 启用），未装打 ⚠ 并给精确安装命令。蒸馏探测独立报一行（distill/ 在否、PyYAML 齐否）。**装不装由用户定，不装不影响任何功能。**
- 自测：`D:\python\python.exe scripts/selftest.py`（合成数据全链路，不依赖真实素材；需能定位到库根或已设 MATERIAL_PARSER_CACHE）。
